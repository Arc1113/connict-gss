# Security policy

## Supported releases

Only the latest release published from this repository is supported with
security fixes. Release downloads must have a valid Authenticode signature and
match the SHA-256 checksum published with the same GitHub release.

## Reporting a vulnerability

Use GitHub's private vulnerability-reporting feature for security or privacy
reports. Do not open a public issue when a report contains exploit details,
credentials, personal information, ceremony data, QR tokens, or information
about a potentially compromised release.

Include the affected version or commit, the observed behavior, reproduction
steps that do not contain real ceremony data, and any relevant signature or
checksum result. Maintainers will acknowledge a complete report as soon as
practical, investigate it privately, and coordinate remediation and disclosure.

If a signing key, signing request, or published artifact might be compromised,
the release will be withdrawn while the maintainers notify SignPath and verify
the source and build history.

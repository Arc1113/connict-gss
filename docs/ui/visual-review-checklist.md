# Visual Review Checklist

Use the real authenticated routes and realistic data. Save evidence for the
required viewports.

## Hierarchy and content

- [ ] One purpose is visually dominant.
- [ ] Critical information appears before supporting information.
- [ ] Labels are concise and sentence case.
- [ ] Recovery text is specific.
- [ ] No fake metric, chart, marketing copy, or unrelated panel appears.
- [ ] Long names/programs wrap naturally.
- [ ] Missing optional content leaves no awkward gap.

## Layout

- [ ] Alignment is deliberate.
- [ ] Related items share spacing.
- [ ] Section boundaries do not depend on nested cards.
- [ ] No horizontal overflow.
- [ ] Required content fits the viewport or uses approved page scrolling.
- [ ] Focus rings are visible and unclipped.
- [ ] Controls meet target-size guidance.

## Visual system

- [ ] Colors use documented semantic roles.
- [ ] Essential status does not depend on color.
- [ ] Borders/radius/shadow are restrained.
- [ ] No decorative gradient, glow, glass effect, or excessive pill appears.
- [ ] Typography remains readable at the target distance/device.
- [ ] Motion is purposeful and reduced-motion safe.

## Scanner states

- [ ] Ready
- [ ] Processing
- [ ] Success
- [ ] Invalid
- [ ] Duplicate/completed
- [ ] Ineligible or honestly documented test limitation
- [ ] Ceremony inactive
- [ ] Server request failed
- [ ] Reverb disconnected
- [ ] Reconnected
- [ ] Missing information
- [ ] Long name

## Stage states

- [ ] Loading
- [ ] Idle
- [ ] Presented
- [ ] Long name/program
- [ ] Missing photo
- [ ] Missing honors
- [ ] Missing audio
- [ ] Disconnected without technical warning
- [ ] HTTP recovered
- [ ] Cleared

## CSV import states

- [ ] Upload/no file
- [ ] Mapping with realistic samples
- [ ] Mapping validation error
- [ ] Ready rows
- [ ] Warning rows
- [ ] Blocked rows with recovery
- [ ] Long graduate/program/message
- [ ] Confirmation processing/lock
- [ ] Completion summary
- [ ] Expired/failed state or honestly documented automated limitation
- [ ] Access denied

## QR preparation and print states

- [ ] Ceremony selected
- [ ] Empty ceremony/no matches
- [ ] Filtered selectable list
- [ ] Empty/invalid/over-limit selection recovery
- [ ] Individual ready card
- [ ] Long graduate and program
- [ ] Data encoder without regeneration
- [ ] Administrator regeneration confirmation and blocked state
- [ ] A4 individual print at 100% scale
- [ ] A4 four-card batch with unsplit cards
- [ ] Grayscale/high-contrast QR and text
- [ ] No visible token, remote asset, clipped content, or print overflow

## Phase 6 scanner states

- [ ] Manual fallback closed and expanded
- [ ] No lookup matches
- [ ] Lookup results with long names
- [ ] Lookup processing through the existing scan result
- [ ] Duplicate Enter preserves the confirmed result
- [ ] Pointer focus recovery does not trap keyboard navigation

## Phase 7 stage-control states

- [ ] Empty controlled queue with dominant current/next action
- [ ] Ordered queue with long graduate and program names
- [ ] Current graduate, local audio ready, and missing-audio guidance
- [ ] Selected out-of-order graduate with explicit confirmation
- [ ] Skipped graduate and returned tail position
- [ ] Command pending, safe failure, disconnected, and recovered
- [ ] Holding active and restored current graduate
- [ ] Automatic active, automatic paused, and paused scan remaining waiting
- [ ] Stacked 1024 px layout preserves hierarchy and table-owned overflow
- [ ] Audience stage remains free of queue, controls, and technical status

## Phase 8 audio states

- [ ] Graduate detail shows uploaded audio awaiting review.
- [ ] Graduate detail shows approved audio with timestamp/reviewer.
- [ ] Graduate detail shows rejected audio and notes without exposing storage
      paths.
- [ ] Replacement guidance states that approval is cleared.
- [ ] Stage control distinguishes approved audio from live-announcer fallback.
- [ ] Replay disabled state is visible and not color-only.
- [ ] Audience stage remains unchanged for missing, rejected, or unapproved
      audio.
- [ ] Audio review controls and native preview remain keyboard reachable.
- [ ] Long announcement names and review notes wrap without horizontal overflow.

## Phase 9 operational-support states

- [ ] Scan-log, stage-event, audit-log, report, and backup pages use calm
      operational hierarchy, not analytics cards or charts.
- [ ] Filter rows wrap without horizontal page overflow at 1024×768.
- [ ] Export and reset actions are visually distinct and not adjacent in a way
      that invites operator mistakes.
- [ ] Backup and restore guidance is concise and does not expose secrets.
- [ ] No CSV output, page, or manifest metadata exposes QR tokens or storage
      paths in ordinary browser views.

## Phase 10 deployment-device pass

- [ ] Scanner `/scanner` is viewed from the server LAN URL in the approved
      browser profile.
- [ ] Audience `/stage` is viewed from the server LAN URL on the projected
      display.
- [ ] Browser fullscreen hides chrome, tabs, taskbars, notifications, and mouse
      pointer from the audience.
- [ ] Stage text remains readable at the actual projector/LED resolution.
- [ ] Stage audio activation and output-device selection are visibly confirmed
      before audience arrival.
- [ ] Refreshing scanner, stage-control, and stage after service restart does not
      reveal debug or technical details.
- [ ] No deployment script output, terminal, admin page, or backup page appears
      on the audience display.

## Anti–AI-slop final pass

- [ ] No equal card grid drives hierarchy.
- [ ] No cards inside cards.
- [ ] No oversized marketing heading.
- [ ] No unnecessary icon beside each heading.
- [ ] No ordinary label is styled as a badge without reason.
- [ ] No audience-facing operator/technical UI remains.
